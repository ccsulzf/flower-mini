# 花艺工作台可维护性重构设计

## 意图

在不改变当前底部精准选择交互、作品持久化结构和云端接口的前提下，清理旧版工具栏残留，收敛选择状态，降低工作台页面与组件之间的事件耦合，并统一花材缩略图生成入口。

## 范围

- 删除已经没有入口的旧版 `studio-flower-toolbar` 及相关状态和布局数据。
- 将选择状态从多个互相约束的 ref 收敛为一个判别联合状态，并保留现有公开行为。
- 将选择动作与素材选择动作从页面提取到专用 composable，页面继续负责生命周期、保存和导航。
- 提取共享花材缩略图工具，供素材面板和选择面板复用。
- 修正无效的 `pickScope` 透传：分类聚焦时按花朵/叶材降低非目标透明度。

## 非目标

- 不改变作品、草稿或云端 schema。
- 不改变底部面板的视觉设计和用户操作路径。
- 不重写 Canvas、SVG、Vue 三套渲染器；渲染一致性另行处理。
- 不新增测试文件，不运行可能修复或安装依赖的命令。

## 方案取舍

考虑过一次性拆分整个 534 行页面，以及仅删除死代码。前者改动面过大且当前没有可运行的回归测试；后者不能解决选择状态继续膨胀的问题。采用渐进式方案：先删除旧路径，再收敛状态并提取纯 UI/动作逻辑，保留启动和保存流程原位。

## 约束

- Vue 文件继续使用 `<script setup lang="ts">`。
- 页面内 composable 放在 `src/pages/flower-studio/composables/`，不参与路由扫描。
- 保留所有现有未提交改动，不触碰用户删除的文档、测试和素材。
