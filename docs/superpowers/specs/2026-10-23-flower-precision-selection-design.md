# 花枝精准选择设计

## 意图

解决手机端花材重叠后细草、细枝无法直接点中的问题。用户不需要理解图层、编号或分组，只需先告诉系统想选“花朵”还是“草叶”，再在目标附近点击。

## 第一版范围

- 画布右侧提供常驻的悬浮“选取”入口。
- 入口第一层展示“全部 / 花朵 / 草叶”；“花朵”包含主花和配花，“草叶”对应 foliage。
- 选择花朵或草叶后，第二层仅展示作品中实际使用的具体素材，按 `materialId` 分组，并显示素材名称和使用数量。
- 选择具体素材后，非目标花材降低透明度并退出触控竞争，目标花材获得更宽松的触控区域。
- 点击目标后继续使用现有花枝编辑工具；悬浮栏的上一枝、下一枝仅切换同一 `materialId` 的实例，并显示“名称 序号/总数”。
- 所有层级回退按钮统一叫“返回”：实例状态返回具体素材列表，具体素材列表返回花朵/草叶大类。
- 当前选中花枝使用明显轮廓和顶部控制点反馈。
- 退出筛选后恢复全部素材的显示和常规直接选取。
- 具体花枝切换统一由悬浮栏负责；花朵编辑面板不再重复显示位置、高度、大小滑杆和上一枝/下一枝导航。
- “前移 / 后移”分别将当前花枝直接置于所有花材最前或最后，避免只交换一个不重叠的相邻项而没有视觉反馈。
- 素材调整工具栏固定在画布左侧中部，使用竖向“图标 + 文字”按钮；颜色面板从工具栏右侧展开。右侧继续保留素材精准选择悬浮栏。

## 非目标

- 不增加作品分组、多选或图层面板。
- 不改变作品持久化结构、云端 schema 或历史记录结构。
- 不实现“只看此枝”和候选缩略图；这些可在第一版体验验证后追加。

## 交互约束

- 拖动已选花枝期间不切换选择。
- 选择到具体花枝后，只有当前花枝保留拖动权限；同一素材的其他实例也不能拦截或响应拖动，直到用户通过悬浮栏切换当前枝或退出选择。
- 切换类别时结束当前拖动并清除当前选择，避免类别与选择不一致。
- 当前类别没有素材时禁用对应按钮。
- 当前具体素材被删除到 0 枝时，自动返回当前大类的具体素材列表。
- 删除、撤销或重做导致选择失效时，保留筛选模式但清除无效选择。
- 筛选是临时 UI 状态，不保存进作品。

## 方案取舍

考虑过原位置循环选择、长按候选菜单和底部花枝列表。前两者仍要求在拥挤画布上精细操作；底部列表虽然准确，但查找具体花枝的认知成本更高。采用悬浮分类筛选，让系统先排除错误类别，再复用用户熟悉的画布定位和现有编辑工具。
