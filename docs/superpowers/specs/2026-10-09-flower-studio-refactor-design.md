# 插花工作室重构与图片完成流程

日期：2026-10-09

## 目标与范围

将现有插花 Demo 的共用组件、领域数据、工具方法和编辑操作拆到明确的位置，保持已经确认的上下布局、花材连接点、拖动、选中圈与色板交互。

完成流程改为：点击「完成」→ 自动生成当前作品图片 → 面板展示图片预览 → 用户点击保存到相册或分享图片。完成面板移除手动生成的额外步骤，以及保存/恢复作品、导入/导出/复制/粘贴 JSON 的操作。

独立「JSON 生成花束」页面继续存在，使用共用解析器和画板，不覆盖工作室作品。这是对“和 JSON 的动作就不要了”的范围解释：去掉工作室完成流程中的 JSON 操作，不删除此前创建的独立预览工具。

不增加依赖，不接入云端素材、账号同步或上传，不修改现有花朵 SVG，不改生成声明、第三方模块及无关用户改动。

## 结构与职责

### 类型与素材目录

- `src/models/artwork.ts`：FlowerKind、VaseName、Stem、Artwork 及共享触摸事件类型。保留 version=2、vase="花束" 和 flowerScale 等兼容字段。
- `src/config/flower-materials.ts`：花材目录、花器选项、背景选项、色板和默认作品工厂。默认作品每次构造新的花枝对象，不共享可变数组。
- 页面专用的 StudioTab 留在工作室目录，避免把面板概念放进领域模型。

### 共享组件与样式

- `src/components/flower/`：FlowerBoard、FlowerStem、FlowerBloom、FlowerVase、FlowerBouquet。
- `src/styles/flower-studio.scss`：工作室语义样式变量，替代跨页面引用 Demo 内部样式。
- 组件通过 props 接收数据，通过事件请求操作，不直接访问编辑 store。
- 顶部页面操作、底部素材入口、素材面板、选中花编辑栏和完成面板保留为页面内组件。
- 使用明确的组件导入；不为复用而强制全局注册页面专用组件。

### 共享工具

- `src/utils/flower/artwork.ts`：JSON 校验与单层转义解包、快照复制、背景颜色与花器锚点、花材确定性绘制参数。
- `src/utils/flower/arrangement.cjs` 与对应 `.d.cts`：现有坐标约束和拖动数学，保留离线 Node 测试兼容方式。
- `src/utils/flower/svg-artwork.ts`：SVG 编码与组合，原 SVG 文件随共享素材引用迁移，内容不改；保留已校准的连接点和花茎在后、花头在前的绘制顺序。
- `src/utils/flower/render-artwork.ts`：Canvas 作品绘制，使用共用尺寸与素材参数。
- `src/utils/flower/artwork-history.ts`：隔离的快照历史，继续保留最近 30 步。

### 编辑 store

新增 setup 风格 Pinia `src/stores/artworkStore.ts`，管理：

- 花枝、花器、背景、选中花枝 ID 和下一枝 ID。
- 选中花枝、可撤销、可重做、可清空、可前移、可后移等派生状态。
- 添加、复制、删除、清空、换色、切换花器和背景、前后层调整。
- 创建独立快照、撤销、重做、作品替换。
- 拖动开始姿态、更新约束与一次拖动只记一条历史的领域边界；触摸坐标和移动阈值由 hook 管理。

所有编辑通过 store action 完成。无变化的操作不生成历史；新编辑清除重做记录；历史与当前作品互不共享可变花枝对象。

进入新的工作室页面时初始化默认作品、清空选中与历史，保留原有“新打开 Demo 从默认作品开始”的行为。打开完成预览、返回编辑不重新初始化。

### 页面与 hooks

- `src/hooks/useFlowerStudioLayout.ts`：设备可用区域、上下工具栏留白、画板缩放和略上移、花朵浮层定位。色板按展开最大高度定位，开关色板不跳位。
- `src/hooks/useFlowerDrag.ts`：触摸起点、位移阈值、拖动开始/更新/结束/取消；调用 store 操作，不处理素材读取。
- `src/hooks/useArtworkImage.ts`：当前页面 Canvas 实例、图片生成、预览、保存和分享。替代现有混合 JSON、缓存和图片功能的 useArtworkFiles。
- 页面保留 activeTab、showFinish、showFlowerTools、toolsColorsOpen 等临时展示状态。完成、撤销等组合交互由页面协调 store 与 hooks。
- JSON 页面继续以独立 ref 管理输入、错误和预览作品；仅依赖共享模型、解析器和画板。

## 已确认交互必须保留

- 添加花材只添加，不自动打开浮动编辑栏。
- 点击画板中的花朵才打开编辑栏；拖动结束不误弹编辑栏。
- 色板默认收起；选色后保持展开；再次点颜色或进行其他操作时收起。
- 展开、收起或换色时浮层不跳位置，换色不改变花枝姿态。
- 顶部页面操作和底部素材入口在编辑花朵时保持显示。
- 长屏作品略上移，短屏不截掉花枝；拖动与浮层使用同一画板坐标。
- 清空可撤销，重做顺序正确，层次边界按钮置灰。

## 完成、预览、保存、分享

1. 点击完成时收起素材和花朵编辑栏，打开图片结果面板。
2. 捕获当时作品的独立快照，清除上一张结果与旧错误，立即开始生成图片。
3. 生成中显示状态并禁用保存、分享，防止重复生成。
4. 成功后面板显示图片，点击图片可放大预览；底部提供「保存到相册」「分享图片」。
5. 保存调用平台相册 API。分享由用户按钮触发微信图片分享菜单，不自动发送消息，不上传文件。
6. 微信分享能力通过运行时 API 能力检测确认；不支持时提示可保存图片后分享。其他平台不调用 wx，给出同样的保存提示。
7. 用户取消分享或保存不当作业务失败。权限拒绝和生成错误给出简短提示。
8. 生成失败时显示错误与「重新生成」，不显示旧图片；可关闭面板继续编辑。
9. 每次重新点击完成都生成新快照，避免修改作品后分享上一次图片。若面板在异步任务期间关闭，完成结果不得自动重新打开面板。

图片不包含按钮或选中圈。保留当前 698×1000 的作品导出尺寸和两倍 PNG 输出，不在本次重构中改变导出渲染方式。

## 验证与验收

- 迁移现有离线测试的文件引用，继续验证 JSON、历史、几何连接、交互和布局；避免用源码文本替代行为测试。
- 新增 store 行为测试，使用独立 Pinia 实例验证初始化、选择、编辑、历史与拖动事务。
- 新增完成流程测试：自动生成、生成中防重入、失败重试、旧图片清除、用户触发保存/分享和取消处理。
- 验证 JSON 页面生成预览不会修改编辑 store。
- 执行 `node --test tests/*.test.cjs`、修改文件的 Vue 编译和只读差异检查。
- 未经明确授权，不运行 pnpm/npm/corepack 等可能修改依赖的命令，不直接修改 node_modules。
- type-check、lint、小程序构建及微信真机生成/保存/分享若未执行，交付时明确列为未验证；离线平台替身不代表真实微信联调。

验收结果：工作室页面主要负责组合组件与展示交互；JSON 页面不再跨页面引用 Demo 内部实现；点击完成无需额外点生成按钮即可得到图片预览，预览仅保留图片相关操作；现有编辑效果和行为不回退。
