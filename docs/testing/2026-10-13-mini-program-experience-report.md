# 鲜花创作小程序全流程体验测试报告

测试日期：2026-10-13  
测试环境：微信开发者工具 2.02.2609231 RC、iPhone 12/13 (Pro) 模拟器  
测试入口：`pages/flower-studio/flower-studio-page`

## 测试范围

- 首页空状态与主操作
- 花材、容器、背景三个编辑面板
- 花材连续添加、撤销、重做和极限数量
- 完成作品、作品详情、贺卡、我的作品完整链路
- 页面配色、按钮层级、面板结构与文案一致性

## 结论

主链路可以完成：选择花材 → 切换容器/背景 → 完成作品 → 查看详情 → 制作贺卡 → 在作品集中查看。撤销和重做在大量花材下仍可用，作品详情和贺卡也能渲染。

当前最需要处理的是花材数量没有产品级上限。实测连续添加到 99 枝后仍可继续创建，源码和测试也明确允许超过 48 枝。大量相同花材几乎完全重叠，视觉上只像 3～4 枝；切换容器、完成作品和进入作品集时，开发者工具多次出现“数据传输长度过长”警告。此状态可以完成流程，但作品状态体积、渲染成本和用户可理解性都已经失控。

## 缺陷与改进建议

### P1：花材数量无上限，极限状态触发数据过长警告

复现：打开花材面板，连续点击同一种花材，添加到 99 枝，再切换容器、背景并完成作品。

实际结果：

- 99 枝仍被完整写入创作状态，源码没有硬上限。
- 同类花材按少量固定位置循环落点，99 枝在画面中严重重叠，肉眼只像少数几枝。
- 多个页面切换阶段出现“数据传输长度过长”。
- 用户界面没有当前数量、建议数量或容量提示。

建议：设置清晰的产品上限，推荐 48 枝；在花材面板显示 `已选 12/48`。达到上限后禁用所有添加按钮，并给出常驻说明或明确 Toast。保存和云端校验使用相同上限，避免前后端规则分裂。

### P1：添加大量相同花材时缺少有效排布

实际结果：落点和角度只在少数预设值间循环，后续花材直接覆盖前面的花材。数量增加没有形成更丰满的构图，也无法从画面判断真实数量。

建议：根据现有数量动态扩大横向分布和高度层级；相同素材增加轻微缩放、角度和纵向扰动；接近容量时优先填补空区。至少保证新增花材在视觉上可识别。

### P1：完成与保存的语义不清晰

实际流程：点击“完成作品”时作品已经保存并进入详情，同时创作页状态被清空；详情页顶部仍显示“保存”，该按钮实际含义是保存图片；作品集空状态又写着“点击‘保存作品’”。

风险：用户容易误以为作品尚未保存，或不知道“保存”是保存到相册。

建议：

- 详情页“保存”改为“保存图片”或“保存到相册”。
- 作品集空状态改为“完成插花后，作品会自动保存在这里”。
- 完成按钮执行云端保存时使用“正在保存作品…”反馈，成功后提示“作品已保存”。

### P2：编辑面板遮挡作品，选择时无法完整预览结果

花材、容器和背景面板占据屏幕下半部。作品虽会上移，但花瓶或花束下半部仍被面板遮挡；选择容器时尤其难判断花脚与容器口是否匹配。

建议：面板打开时按面板实际高度缩放并上移整幅作品，保证花头和容器完整可见；也可以提供半屏/折叠两档高度。

### P2：主操作层级在页面间不统一

- 首页“完成作品”使用带装饰字符的强主按钮。
- 详情页“编辑、分享、保存、贺卡”全部是尺寸接近的小型文字按钮，缺少主次。
- 花卡页“填写内容、保存图片、分享贺卡”均放在底部同一层级，点击区域和视觉权重偏弱。
- 作品集中的“复制、删除”与卡片正文距离较近，删除虽然有二次确认，但视觉上容易误触。

建议：每页只保留一个主操作。详情页以“继续编辑”或“制作贺卡”为主；导出和分享放次级操作区。花卡页以“填写内容/完成填写”为主，“保存图片、分享”在内容完成后再强调。

### P2：作品命名导致列表难以区分

默认名称都是“花意 M月D日”。同一天完成多件作品时，作品集会出现相同标题和日期，只有缩略图能区分。

建议：默认名称加入当天序号，例如“花意 10月13日 · 02”，或者在完成时允许快速命名。

### P2：花卡编辑的默认内容与字数反馈容易误解

祝福语区域视觉上显示默认文案，但计数显示 `0/120`，因为默认文案是 placeholder。用户可能认为该文案已经写入成品。

建议：如果默认祝福会出现在成品中，就将其作为真实初始值并计数；如果只是示例，降低文字对比度并标明“示例”。

## 已通过项目

- 空作品时撤销、重做、清空正确禁用。
- 添加花材后撤销可用；撤销后重做可用；重做后状态恢复。
- 99 枝状态下可以切换花瓶和花束容器。
- 99 枝状态下可以切换纯色背景。
- 99 枝状态下可以完成作品并进入详情。
- 极限作品可以进入贺卡页并正常显示编辑面板。
- 完成后的作品能出现在“我的作品”列表。
- 本轮未执行分享、保存图片和删除，避免向外部发送内容或删除现有数据。

## 建议修复顺序

1. 统一前端、云端和模型层的花材数量上限，并补充数量反馈。
2. 修复大量花材的落点算法和状态体积问题。
3. 统一“完成作品 / 保存作品 / 保存图片”的文案语义。
4. 调整面板打开时的作品缩放与位移，确保容器完整可见。
5. 统一详情、花卡和作品集的按钮主次与危险操作样式。
