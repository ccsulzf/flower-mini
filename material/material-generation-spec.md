# 花材与叶材统一素材生产规范（草案）

- 状态：讨论中
- 日期：2026-10-31
- 适用项目：`flower_mini`
- 适用范围：花材、叶材

## 1. 背景

此前的生产方式是参考项目中已有 SVG，继续制作相同风格但不同品种的 SVG。实践表明，大模型直接模仿现有 SVG 的造型和路径风格时，植物辨识度、手绘质感和品种间的一致性都不理想，无法稳定扩展素材库。

新的生产方式将视觉创作与工程化处理拆开：先利用图片模型生成风格统一、植物结构准确的位图，再由人工使用 VTracer 转成 SVG，最后对 SVG 进行项目适配、分层着色和性能优化。

## 2. 目标

1. 建立一套可长期扩展的统一视觉语言，而不是逐张模仿旧 SVG。
2. 让花材和叶材具有明确的植物品种辨识度、自然形态与手绘质感。
3. 以“独立花头 + 无叶花茎”为统一结构，让不同花材能够稳定拼接、调高和组合。
4. 让最终 SVG 适用于微信小程序中的缩放、旋转、组合和换色。
5. 用户改变花色时，保留自然明暗以及花蕊、花萼等固有色；叶材保持自身植物色。
6. 建立明确的生产、返工和验收流程，避免用后期路径修补掩盖不合格的原始图片。

## 3. 非目标

本轮不重做以下素材：

- 花器；
- 花束包装；
- 背景和场景；
- 页面纸纹、印章、文字等装饰元素。

本规范暂不直接规定项目数据模型和渲染器的最终代码结构。相关实现应在素材结构标定完成后另行设计。

## 4. 视觉方向

### 4.1 核心风格

统一风格定义为：

> 东方古典植物图鉴式手绘：自然写生比例，克制舒展的形态，低饱和矿物色与植物色，柔和透明的手绘层次，少量细线刻画结构，轮廓清楚但不描死。

整体气质由以下三部分共同构成：

- 古典植物图鉴的准确结构：花、叶、枝的品种特征清楚；
- 手绘媒介感：具有水彩、色铅笔或细笔线条的自然层次，但不过度写实；
- 东方插花的克制气质：花型自然、留白明确，不把花头处理成夸张、甜腻或机械对称的装饰图标。

### 4.2 参考方向

- [历史植物插画家与古典植物插画](https://www.shoppingdesign.com.tw/post/view/5828)
- [手绘植物书籍合集](https://www.douban.com/doulist/817940/)
- [Japanese Floral Art](https://www.pinterest.com/renblue/japanese-floral-art/)
- [古典手绘植物图鉴](https://www.pinterest.com/alicehuang98499/%E5%8F%A4%E5%85%B8%E6%89%8B%E7%B9%AA%E6%A4%8D%E7%89%A9%E5%9C%96%E9%91%91/)

参考内容用于提炼植物结构、手绘语言和自然形态，不直接复制具体作品。

### 4.3 必须具备的视觉特征

- 植物品种可辨识，关键花瓣、花蕊、叶形和生长结构不能被风格化到失真；
- 独立花头具有自然朝向和明确视觉重心；
- 花瓣、花萼和花茎连接关系符合品种结构；
- 配色低饱和、温和、偏自然植物色；
- 花瓣具有可归纳的基色、亮部、半影和深部褶皱；
- 手绘线条使用暖灰褐、灰绿或区域对应的深色，不使用生硬纯黑描边；
- 小尺寸下轮廓和主要结构仍然清楚；
- 不追求摄影式写实，不依赖大量噪点、颗粒和极细刻线表达质感。

### 4.4 禁止出现的内容

生成图片中不得包含：

- 纸张背景或纸张纹理；
- 文字、拉丁学名、题签、印章和边框；
- 花瓶、花盆、包装和场景陈设；
- 投影、地面接触阴影和环境光斑；
- 昆虫、其他植物或无关装饰；
- 被画布裁切的花瓣或花萼；
- 为营造复古感而加入的污渍、折痕和扫描噪点。

## 5. 素材结构

### 5.1 基本单位

花材统一以“独立花头 + 无叶花茎”为基本结构。花头位图和最终花头 SVG 不包含叶片或向下延伸的长花茎；无叶花茎使用单独 SVG，并与花头在连接点拼接。叶材仍以独立完整叶枝素材存在。

最终 SVG 至少需要能够区分以下视觉语义：

- 花瓣可调基色；
- 花瓣明暗层；
- 花蕊、花药、果实等固有结构色；
- 花萼等固有色；
- 结构线等固有色或线条层。

实际 SVG 不强制使用特定的 `<g>` 数量或命名，工程化阶段可依据路径结构调整；但上述语义必须能够稳定识别和映射。

### 5.2 单一姿态

每个品种目前只制作一个默认姿态，不生产直立、左展、右展等多姿态变体。默认姿态应优先表现该品种最有辨识度、最适合插花组合的自然朝向。

### 5.3 主体与花茎

最终的完整花材由两部分拼接：

1. 独立花头：由位图经 VTracer 转换和工程化处理后的最终 SVG；
2. 无叶花茎：从花头下端向下延伸、用于调节完整花材高度和插入花器深度的简化 SVG。

独立花头下端必须提供明确的 `stemAnchor`。花头保留必要的花萼或短连接段，无叶花茎位于花头后方并与其重叠，从而遮住拼接缝。

简化花茎由 AI 助手直接编写为 SVG，不经过图片生成、VTracer 转换和主体工程化流程。花茎使用少量贝塞尔曲线和有限色阶，不包含复杂纹理；纵向调整长度时，线宽不能明显随高度变化。

每个品种使用一个 `stem.svg`。

## 6. 着色规则

### 6.1 用户可调部分

用户选择的颜色主要改变花瓣主色。

花瓣内部不采用单色整体替换，而应根据主色生成或映射出协调的：

- 高光；
- 基色；
- 半影；
- 深部褶皱。

### 6.2 保留固有色的部分

以下部分默认不随用户花色直接替换：

- 花蕊和花药；
- 萼片；
- 枝条；
- 叶片和叶脉；
- 果实或其他具有明确品种特征的结构。

当用户选择很深或很浅的花色时，可以对固有结构色做有限的亮度或对比度适配，但不能改变其基本色相关系和植物辨识度。

### 6.3 叶材

纯叶材暂不纳入“花色”换色逻辑。是否为叶材提供有限的绿调选择，作为待确认项保留。

## 7. 风格一致性策略

采用“统一总规范 + 结构家族标定样本”的方式，不使用单条提示词直接批量生产全部品种。

### 7.1 总规范

所有结构家族共享：

- 相同的整体风格描述；
- 相同的构图和背景规则；
- 相同的线条粗细区间；
- 相同的明暗层级原则；
- 相同的饱和度与对比度范围；
- 相同的细节复杂度上限；
- 相同的最终使用尺寸验收方式。

### 7.2 结构家族

不同结构的植物分别建立标定样本。当前建议覆盖：

- 重瓣或密集型主花；
- 开放型主花；
- 分枝型配花；
- 穗状或纵向花材；
- 细碎或羽状叶材；
- 面状或线状叶材。

以上家族划分是当前建议，尚未完成最终确认。后续可以根据现有素材目录合并或细分。

### 7.3 标定原则

1. 先选择结构差异明显的少量植物生成标定样本；
2. 确认唯一主画风后，再扩展结构家族；
3. 新品种生成时同时参考总规范和对应家族母版；
4. 每批新品种都必须与家族母版并排比较；
5. 风格发生漂移时回到图片生成阶段，不在 SVG 阶段强行修补。

## 8. 生产流程

### 8.1 总流程

```text
确定品种与结构家族
  → 编写标准化生成提示词
  → AI 生成位图候选
  → 位图视觉验收
  → 用户使用 VTracer 转为 SVG
  → 独立花头 SVG 工程化处理
  → 生成无叶花茎 SVG
  → 独立花头与完整花材验收
  → 通过后进入正式素材库
```

### 8.2 图片生成

由 AI 助手直接生成位图并交付用户。

图片生成阶段负责：

- 植物学结构和品种辨识度；
- 统一手绘风格；
- 透明画布；
- 单个独立花头构图和固定安全留白；
- 品种最具辨识度的单一自然朝向；
- 可被 VTracer 识别的清晰色块与边界；
- 避免不适合矢量化的噪点和微小纹理。

图片生成阶段不负责最终 SVG 路径组织和项目着色标记。

图片的具体分辨率、宽高比和安全留白比例需要在标定阶段量化。

### 8.3 VTracer 转换

由用户使用 VTracer 将通过视觉验收的位图转换为 SVG。

VTracer 阶段需要重点控制：

- 主要轮廓不能丢失；
- 花瓣明暗不能被合并成单一色块；
- 不能产生大量无意义碎片；
- 细线、叶脉和花蕊应在实际使用尺寸下有保留价值；
- 路径数量和文件体积应保持可继续优化的范围。

具体 VTracer 参数需要通过标定样本试验后确定，不在当前草案中预设。

### 8.4 SVG 工程化

由 AI 助手接收 VTracer 输出并完成：

- 清理无意义路径和孤立碎片；
- 合并可以安全合并的同类色块；
- 规范 `viewBox`、透明边界和素材占比；
- 建立稳定的底部插入锚点、视觉中心和旋转基准；
- 识别花瓣基色、明暗和固有结构色；
- 添加项目所需的颜色映射标记或分组；
- 控制 SVG 文件体积和路径复杂度；
- 处理微信小程序兼容性；
- 接入新的素材数据模型和渲染流程；
- 在实际创作台中验证缩放、旋转、换色和组合效果。

### 8.5 素材生产工作区

`material/` 是素材生产工作区，`src/subpackages/material-admin/assets/` 是最终进入项目的正式素材库。生产工作区保留原始位图、VTracer 输出和工程化结果，便于对照、返工和验收。

目录约定如下：

```text
material/
├── material-generation-spec.md
├── index.html
└── assets/
    ├── catalog.json
    └── <material-id>/
        ├── material.json
        ├── source.png
        ├── traced.svg
        ├── traced-detail.svg
        ├── flower.svg
        └── stem.svg
```

每个品种的 `material.json` 只保存项目最终运行需要的信息，不记录原始位图、VTracer 文件或生产状态。当前字段包括：`id`、`category`、`name`、`group`、`introduction`、`flowerMeaning`、`version`、`colors` 和 `geometry`。其中 `geometry` 至少包含 `width`、`flowerHeight`、`stemHeight` 和 `stemAnchor`；`stemAnchor` 使用相对于花头 SVG 视口的坐标，作为花头与无叶花茎的连接基准。

只有 `material.json`、`flower.svg` 和 `stem.svg` 属于最终运行资产。`source.png`、用户提供的原始 VTracer SVG，以及 `traced.svg` / `traced-detail.svg` 等中间追溯文件不进入小程序素材包。

`assets/catalog.json` 仅供预览页发现品种目录，内容是品种 ID 列表，不重复保存品种详情或生产状态。

### 8.6 HTML 预览页

预览页使用原生 HTML、CSS 和 JavaScript，不安装或引入第三方依赖。页面通过本地静态服务器访问，不要求支持 `file://` 直接双击运行，也不依赖启动 uni-app 或微信小程序。

页面先读取 `assets/catalog.json`，再加载每个品种目录中的 `material.json` 并生成预览卡片。生产文件按固定命名规则定位；某一阶段文件缺失时，页面显示该阶段尚未完成。

每张卡片需要区分并展示：

- 独立花头：`flower.svg`；
- 完整花材：独立花头与无叶花茎拼接后的结果；
- AI 原始位图：`source.png`；
- VTracer 原始 SVG：`traced.svg` 或当前采用的详细追溯版本 `traced-detail.svg`；
- 最终花头 SVG；
- 无叶花茎 SVG。

“完整花材”是单个独立花头与无叶花茎拼接后的完整单枝，不是多枝花束或多品种插花。

预览页至少支持：

- 实时切换花色，并保留花瓣明暗以及花蕊、花萼等固有色；
- 调节花茎长度并检查连接处；
- 缩放独立花头及完整花材；当前素材只提供一个固定姿态，不在预览页提供姿态切换；
- 切换浅色、深色和透明棋盘背景；
- 点击查看原始位图、VTracer SVG 和最终花头 SVG。

## 9. 返工边界

出现问题时，应回到产生问题的环节处理：

| 问题 | 返回环节 |
| --- | --- |
| 花型不准确、品种难以辨识 | 图片生成 |
| 花头朝向僵硬或不适合插花组合 | 图片生成 |
| 手绘风格漂移、色彩不统一 | 图片生成 |
| 轮廓丢失、色块碎裂、路径异常膨胀 | VTracer 转换 |
| 换色不自然、分层语义错误 | SVG 工程化 |
| 锚点、占比、旋转中心或组合关系不正确 | SVG 工程化或项目实现 |
| 小程序渲染异常或性能不合格 | SVG 工程化或项目实现 |

不得使用复杂的 SVG 手工修补来挽救一张视觉上不合格的原始位图。

## 10. 验收标准

### 10.1 位图验收

- 第一眼能够辨识植物品种；
- 与总规范和对应家族母版风格一致；
- 花瓣、花萼和连接位置关系自然；花头位图不包含叶片或长花茎；
- 构图完整，没有裁切；
- 背景干净，没有禁止元素；
- 主要色块边界适合矢量追踪；
- 不依赖细碎噪点才能成立；
- 缩小到预计使用尺寸后，轮廓和主要结构仍清晰。

### 10.2 SVG 验收

- `viewBox` 正确，透明边界合理；
- 无脚本、外链资源或不受支持的 SVG 功能；
- 没有明显无意义碎片和异常路径；
- 花瓣调色层与固有色层能够可靠区分；
- 深色、浅色和中等明度花色下均保持结构清晰；
- 花蕊、花药、花萼等固有色不被花色污染；
- 文件体积和路径数满足小程序实际运行要求；
- 缩放和旋转时没有明显失真或断裂。

### 10.3 项目内验收

- 独立花头显示正确；
- 独立花头与无叶花茎连接自然，没有明显拼接缝；
- 调整花茎长度时线宽和连接关系稳定；
- 多枝组合时风格、比例和细节密度一致；
- 与现有创作台的选择、拖拽、缩放和旋转操作兼容；
- 花色切换自然，明暗层级保留；
- 在真实微信小程序环境中的显示和性能最终需要单独验证，离线预览不能替代真机或真实运行环境验收。

## 11. 当前已确认的决策

1. 新素材采用复古植物手绘风格；
2. 视觉语言结合古典植物图鉴、手绘媒介感和东方插花姿态；
3. 只重做花材和叶材；
4. 允许调整当前素材模型；
5. 花材统一采用“独立花头 + 无叶花茎”的结构；
6. 用户换色主要改变花朵颜色；
7. 花瓣保留自然明暗，花蕊、花萼保留固有色，叶材保持自身植物色；
8. 采用“统一总规范 + 结构家族标定样本”的生产方式；
9. AI 助手直接生成位图并交付用户；
10. 用户使用 VTracer 转换，AI 助手负责后续 SVG 工程化和项目适配；
11. 每个品种目前只制作一个默认姿态；
12. 完整花材由独立花头与可调长度的无叶花茎拼接；
13. 无叶花茎由 AI 助手直接编写 SVG，不经过位图和 VTracer 流程；
14. `material/assets/<material-id>/` 保留位图、VTracer SVG、最终花头 SVG、运行时 JSON 和花茎 SVG；
15. `material.json` 只保存项目最终运行需要的信息；
16. `assets/catalog.json` 仅供预览页发现品种目录；
17. 预览页使用无依赖的原生 HTML、CSS 和 JavaScript，通过本地静态服务器运行；
18. 预览卡片支持实时换色、花茎长度、缩放和源文件对照；当前不支持姿态切换；
19. 图片统一使用透明画布，并为独立花头保留固定安全留白。
20. 玫瑰已完成第一轮样本：使用彩色 VTracer 结果作为工程化基础，黑白 VTracer 仅保留作对照，不作为最终花头来源。
21. 玫瑰当前保留 `traced-detail.svg` 作为详细追溯版本，`flower.svg` 为对应的最终花头候选；后续验收重点是换色语义、连接锚点和小程序实际渲染。
22. 无叶花茎顶部不额外添加装饰性连接形状；由花头图层遮挡主茎起点，避免产生与原花型不一致的人工接头。
